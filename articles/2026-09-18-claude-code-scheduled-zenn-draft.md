## はじめに

[前回の記事](https://zenn.dev/tomowingweb/articles/2026-09-11-swell-claude-code-template-repository)では、SWELL子テーマ開発のテンプレートリポジトリを整備し、新規案件の環境構築を5分に短縮しました。末尾で予告した通り、今回は **Claude Codeのスケジュール実行（Scheduled Tasks）機能を使って、Zenn記事の下書きを毎週自動生成する仕組み** を作ります。

副業Web制作を続けながら技術アウトプットも並行するのは、正直しんどいです。「作業はしているのに記事が書けない」という状態が続いていました。

- 毎週の作業内容はgitのコミットログとして残っている
- 記事のフォーマットは決まっている
- 何を書くかは作業内容から決まる

ならば **定型的な部分はClaude Codeに任せてしまおう** というアイデアです。毎週月曜日の朝に前週の作業内容を元に記事ドラフトが自動生成され、Zennリポジトリにコミットされていれば、あとは自分で肉付けして公開するだけになります。

## 環境

- Claude Code（CLI）v1.x / Claude Code on the Web
- Node.js 20.x
- zenn-cli v0.5.x
- GitHub（`tomowingweb/zenn-articles` リポジトリ）
- GitHub（`tomowingweb/claudecode` リポジトリ：作業ログの参照元）

## Scheduled Tasksとは

Claude Code on the Web（`claude.ai/code`）では、プロンプトをスケジュール実行する機能があります。cronのように定期的にClaudeセッションを起動し、指定したプロンプトを実行させることができます。

通常のClaude Codeセッションと同じく、リポジトリへのアクセス権限、GitHub MCPツール、ファイル編集・コミット・プッシュの権限を持ったまま動作します。つまり、**人間が操作するClaudeと同じことを、指定した時刻に自動で実行させられる**ということです。

ユースケースは幅広いですが、今回のような「定期的なコンテンツ生成とコミット」には特にマッチします。

## 実装内容

### 全体のフロー

```
毎週木曜 深夜（JST）
    │
    ▼
Scheduled Tasks が起動
    │
    ▼
tomowingweb/claudecode の直近7日分のコミットを取得
    │
    ▼
コミット内容からテーマを選定（WordPress/SWELL優先）
    │
    ▼
記事ドラフトを生成（2000字以上、日本語、published: false）
    │
    ▼
tomowingweb/zenn-articles に articles/YYYY-MM-DD-slug.md として保存
    │
    ▼
git commit & push
    │
    ▼
完了通知（PushNotification）
```

### スケジュール設定

Claude Code on the Webの設定画面から、以下のプロンプトを毎週木曜23:00（JST）に実行するよう設定しました。

```markdown
Zenn記事の下書きを自動生成してコミットしてください。

## リポジトリについて
WordPress/SWELL子テーマ開発者のZenn記事公閉用リポジトリ。
主な技術テーマ：WordPress/SWELLカスタマイズ、Claude Code活用、副業Web制作。

## 手順

### 1. この1週間の作業内容を取得
`git clone https://github.com/tomowingweb/claudecode.git /tmp/claudecode` でクローンし、以下を実行する：
```bash
cd /tmp/claudecode
git log --since="7 days ago" --oneline --no-merges
```
コミットの内容から記事のテーマを一つ選ぶ。
テーマの優先度：WordPress/SWELL > Claude Code活用 > 副業ツール

### 2. 記事ドラフトを作成
今日の日付を取得（`date +%Y-%m-%d`）して、以下の形式でファイルを作成：
...（以下省略）
```

実際にはプロンプト全文が数百字になります。Claude Code on the Webのスケジュール設定UIに貼り付けるだけで完成です。

### 記事生成のロジック

プロンプトの核心は「コミットログからテーマを選ぶ」部分です。以下の優先順位で選定するよう指示しています。

1. **WordPress/SWELL関連**：`add_filter`, `add_action`, SWELLフック、カスタマイザーなど
2. **Claude Code活用**：新機能の試用、ワークフロー改善、MCPの追加など
3. **副業ツール**：GitHub Actions、自動化、テンプレートなど

コミットメッセージに `fix:` や `refactor:` だけのものが多い週は、その変更内容そのものではなく「なぜその変更が必要だったか」というコンテキストを記事テーマにするよう指示しています。

```markdown
## テーマ選定の指示（プロンプト抜粋）

コミットの内容から記事のテーマを一つ選ぶ。
テーマの優先度：WordPress/SWELL > Claude Code活用 > 副業ツール

- fix: や refactor: だけのコミットが多い場合は、その変更が必要になった
  背景・課題を記事テーマとする
- 同一テーマのコミットが複数ある場合は、それをまとめた実装記事にする
- 直前の記事（articles/ディレクトリの最新ファイル）と重複するテーマは避ける
```

### 生成される記事の構成

テンプレートとして以下の見出し構成を指定しています。

```markdown
## はじめに
（前回記事へのリンクと今回の動機）

## 環境
（バージョン情報）

## 実装内容
（コミット内容を元に具体的なコード・手順）

## ポイント
（ハマりどころ・学んだこと）

## まとめ
（結論・次のステップへの予告）
```

この構成は過去の記事と統一されているため、生成されたドラフトをそのままZennのエディタで開いても違和感がありません。

### Zennリポジトリへのコミット

生成した記事ファイルは、スケジュールタスク内で直接 `git commit & push` されます。

```bash
git config user.email "tomo.wingweb@gmail.com"
git config user.name "WING-TM htomo"
git add articles/
git commit -m "docs: YYYY-MM-DD 記事下書きを自動生成"
git push origin main
```

`published: false` を必ずfrontmatterに含めているため、コミットされた段階ではZennには公開されません。確認・加筆してから自分で `published: true` に変えてZenn CLIでプレビュー確認し、最終的にGitHubにプッシュすることで公開する流れです。

## 実際に動かしてみて

この記事自体が、そのスケジュールタスクによって生成された下書きです。

正確には、Claudeが生成したドラフトを私が確認・加筆したものですが、骨格（見出し構成・環境情報・基本的な実装説明）はClaudeが自動で作りました。私が追加したのは：

- 実体験に基づく具体的なエピソード
- 「実際に動かしてみて」のセクション（この部分）
- まとめの一部

体感として、**ゼロから書く場合の6〜7割は自動生成で済んだ**印象です。「何を書けばいいか分からない」という最初の壁がなくなるだけで、継続しやすさが段違いです。

## ポイント

### `published: false` の徹底

スケジュール実行で自動コミットするため、誤って記事が公開されるリスクがあります。プロンプトに複数回 `published: false` を明記し、さらにClaude Codeには「このフィールドは絶対に変更しないこと」と念押ししています。

Zennの仕様上、`published: false` のファイルはGitHubにプッシュされてもZennには反映されないため、この1行が安全弁として機能します。

### コミットログの品質が記事の品質に直結する

スケジュールタスクが生成する記事の質は、参照するコミットログの質に依存します。

- `fix typo` のような雑なメッセージが多い週 → テーマが曖昧な記事になりやすい
- `feat: SWELLのページヘッダーにカスタムクラスを追加する機能を実装` のような具体的なメッセージ → 記事の実装内容が具体的になる

この仕組みを導入してから、コミットメッセージを丁寧に書く習慣がつきました。「後でClaudeが読む」という前提があると、自然と説明的になります。

### スケジュール実行のタイミング

毎週木曜深夜に設定した理由は、**週の後半に作業が多い**という自分のパターンに合わせたからです。月曜〜水曜の作業内容を木曜深夜にまとめる形になります。

金曜の朝にGitHubを確認すると下書きが出来上がっている、という週次リズムができました。

### アクセス制限への対応

Claude Code on the Webのスケジュールセッションは、設定されたリポジトリへのアクセス権限内で動作します。今回は `tomowingweb/zenn-articles`（書き込み対象）と `tomowingweb/claudecode`（読み取り参照元）の両方へのアクセスが必要でした。

セッションのスコープに両リポジトリを含める設定が必要な点は注意してください。スコープ外のリポジトリにはアクセスできず、その場合Claudeは既存記事の傾向を参考に記事を生成するフォールバック動作をします。

## まとめ

Claude Codeのスケジュール実行機能を使って、毎週のZenn記事ドラフト生成を自動化しました。

| 作業 | 自動化前 | 自動化後 |
|---|---|---|
| テーマ選定 | 30分〜（何を書くか悩む） | 0分（コミットから自動選定） |
| 構成・骨格 | 30分〜 | 0分（自動生成） |
| コード例の記述 | 60分〜 | 10分（自動生成を確認・補足） |
| 加筆・仕上げ | 30分〜 | 30分（変わらず） |
| **合計** | **2〜3時間** | **40分程度** |

副業案件をこなしながら毎週記事を書くのは現実的に難しかったですが、この仕組みを導入してからは「ドラフトがあるから仕上げるだけ」という状態になり、継続しやすくなりました。

技術的なアウトプットは、書いた内容が次の案件の引き合いにつながることもあるため、継続できる仕組みを持つことは副業において実利的な意味があると感じています。

次回は、生成された記事ドラフトをより高品質にするために、**過去記事の内容を参照して重複を避け、連載の流れを意識したドラフト生成**を試みる予定です。単発の記事ではなく「連載」として読めるZennマガジンを意識したアウトプットを目指します。
