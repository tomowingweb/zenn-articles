## はじめに

[前回の記事](https://zenn.dev/tomowingweb/articles/2026-09-18-claude-code-scheduled-zenn-draft)では、Claude Codeのスケジュール実行でZenn記事のドラフトを毎週自動生成する仕組みを紹介しました。末尾で予告した通り、今回は **過去記事の内容を参照して重複を避け、連載の流れを意識したドラフト生成** にアップグレードする実装を共有します。

前回の仕組みで数週間運用してみると、次のような問題に気づきました。

- **テーマが被りやすい**：コミットログにSWELLのフック追加が続く週は、前々回の記事と似た内容になってしまう
- **「連載感」がない**：各記事が独立していて、読者が通して読んだときの流れがない
- **「次回予告」が機能しない**：手動で加筆しないと前回記事への言及や次回予告が入らない

副業の合間に毎週書くことを考えると、「ドラフトの質＝公開までの加筆量の少なさ」です。前回記事への自然なリンクや「次回は○○を試みます」という予告まで自動生成できれば、仕上げにかかる時間をさらに短縮できます。

## 環境

- Claude Code on the Web（Scheduled Tasks）
- Node.js 20.x
- zenn-cli v0.5.x
- GitHub（`tomowingweb/zenn-articles`）

## 実装内容

### 課題：過去記事コンテキストをどう渡すか

スケジュールタスクのプロンプトは静的なテキストです。毎週変わる「過去記事の内容」を動的に参照させるには、Claude Code自身に実行時点で過去記事を読み込ませる必要があります。

今回の解決策は **「プロンプトの手順書にファイル読み込みステップを追加する」** ことです。Claudeはタスク実行時に `articles/` ディレクトリを走査し、最新3〜5件の記事を読んだうえでドラフトを生成します。

### 改良したプロンプト構成

前回との差分として、以下のステップを追加しました。

```markdown
### 0. 過去記事の内容を確認する（追加）

`articles/` ディレクトリの最新5件の記事を読み込み、以下を把握する：
- 各記事のテーマ（タイトルとtopicsから判断）
- 最新記事の「まとめ」にある次回予告
- 過去3件で扱ったWordPress/SWELLの機能・フック名

把握した内容を元に：
1. 直近の記事と被るテーマは避ける
2. 最新記事の次回予告があれば、それに沿ったテーマを優先する
3. 「はじめに」では前回記事へのリンクを自然に含める
```

また、記事テンプレートの「まとめ」セクションにも追記しました。

```markdown
## まとめ
（結論の2〜3文）

（下記のテーブル：自動化前後の比較があれば記載）

次回は、（次回テーマの予告を1文で。直近の作業内容から自然に続くテーマを選ぶ）
```

### ファイル走査のステップ詳細

プロンプトに追加した具体的な手順は次の通りです。

```markdown
過去記事の確認手順：
1. `ls articles/ | sort -r | head -5` で最新5件のファイル名を取得
2. 各ファイルの先頭50行を読み込む（frontmatter + はじめに + まとめを把握）
3. 最新ファイル（今回生成するものの直前）の「まとめ」全文を読む
4. 上記から「次回予告」を抽出し、今回のテーマ選定に使う
```

ファイル名は `YYYY-MM-DD-slug.md` の形式で日付順に並んでいるため、`sort -r` で降順ソートすれば最新順に取得できます。

### 実際の生成結果の変化

改良前と改良後で、生成されるドラフトの「はじめに」セクションを比較してみます。

**改良前（過去記事未参照）：**

> SWELLのカスタムフックを活用する機会があったので、実装内容をまとめます。

**改良後（過去記事参照あり）：**

> [前回の記事](https://zenn.dev/tomowingweb/articles/2026-09-18-...)では、Claude Codeのスケジュール実行でZenn記事の下書きを毎週自動生成する仕組みを紹介しました。末尾で予告した通り、今回は過去記事の内容を参照して重複を避け、連載の流れを意識したドラフト生成にアップグレードする実装を共有します。

この記事の「はじめに」そのものが、改良後の自動生成結果です。

### Zennの記事URLルールへの対応

「前回記事へのリンク」を自動生成するには、生成前の時点で前回記事のZenn URLが必要です。

ZennはGitHubと連携している場合、`articles/YYYY-MM-DD-slug.md` のファイルがプッシュされると自動的に `https://zenn.dev/{username}/articles/YYYY-MM-DD-slug` というURLで公開されます（`published: true` の場合）。

`published: false` のドラフトでもURLのスラッグは確定しているため、ファイル名からURLを構築できます。

```markdown
前回記事のURL生成ルール（プロンプト追記）：
- `articles/` ディレクトリの直前ファイルのスラッグ部分（YYYY-MM-DD-slug.mdのslugg部分）を取得
- `https://zenn.dev/tomowingweb/articles/{スラッグ}` を前回記事リンクとして使用
- ただし最新記事が `published: false` の場合は「（前回記事）」と記載し、リンクは仮置きにする
```

この仕組みにより、自分が `published: true` にして公開した後も、リンクが正しく機能します。

## ポイント

### 読み込む記事数のバランス

最初は直近10件を読み込もうとしましたが、それだと：

- トークン消費が増えコストがかかる
- 「どのテーマが被っているか」判断に時間がかかる
- 重複回避が厳しくなりすぎて、有用なテーマを避けすぎる

**直近3〜5件が最適**という結論に至りました。技術記事の場合、3〜4ヶ月前の内容は「復習・深堀り」として同じテーマを扱ってよいからです。

### 連載として機能させるための「種まき」

自動生成を連載として機能させるためには、**前の記事に「次回は○○」という予告を含める**ことが重要です。

改良前は、自分が手動で加筆するときに予告を書いていましたが、改良後は次のルールを追加しました。

```markdown
## まとめの末尾に必ず含める内容（プロンプト追記）

次回は、（直近コミットから見えてくる次週の作業テーマ）を試みる予定です。
単発の記事ではなく「連載」として読めるZennマガジンを意識したアウトプットを目指します。
```

次回のClaudeはこの予告を読んで、その続きとしてドラフトを生成します。こうして**記事から記事へと文脈が引き継がれていく**連載構造が、完全な自動化で実現できます。

### WordPress/SWELL開発との相性

この仕組みはWordPress/SWELLの開発日記として特に機能しやすいと感じています。理由は：

1. **開発が反復的**：フックの追加・カスタマイザーの調整・子テーマの整備など、毎週似た種類の作業が続く
2. **積み上げ型の進化がある**：先週作ったものを今週改善する、というサイクルが連載テーマになりやすい
3. **コミットログが充実しやすい**：変更の理由をコミットメッセージに書く習慣があれば、テーマ選定材料が豊富になる

副業でWordPress案件をこなしながらZennに書いていると、自然と「このカスタマイズはどの案件にも使えそう」という汎用ネタが生まれます。そのネタを逃さずドラフト化できる点が、この自動化の最大の恩恵かもしれません。

## まとめ

Claude Codeのスケジュール実行によるZenn記事自動生成を「連載対応」にアップグレードしました。

| 改善点 | 改良前 | 改良後 |
|---|---|---|
| テーマ重複 | 頻繁に被る | 直近5件を参照して自動回避 |
| 前回記事へのリンク | 手動加筆が必要 | 自動生成 |
| 次回予告 | 手動加筆が必要 | 自動生成（コミットログから） |
| 連載としての一貫性 | 各記事が独立 | 文脈が引き継がれる |

「書くことを継続する」ための仕組みとして、自動化の精度が上がるたびに加筆の負荷が下がっていくのを実感しています。

次回は、この連載生成の仕組みをSWELL子テーマのドキュメント自動生成にも応用する予定です。コードのコメントやREADMEをClaudeに更新させながら、それをZenn記事のネタとして流用する「開発ドキュメントとZenn記事の二重活用」を試みます。
